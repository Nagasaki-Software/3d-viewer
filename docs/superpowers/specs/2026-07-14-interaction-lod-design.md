# 操作中の簡易表示（LOD）設計

## 背景・問題

660MBクラスの巨大STEPアセンブリを変換した結果（三角形数を約半分に削減した後でも）、LAN経由でタッチパネルPCから操作すると実測4fpsしか出ない。draw-callのバッチ化は既に実施済みで効果もあったが、根本的にGPUが処理する三角形数（数百万規模）が一般的なノートPCの内蔵グラフィックスの限界を大きく超えている。三角形数をさらに削ると静止時の見た目が劣化するため、「静止時は精密・操作中だけ軽量」という切り替え方式（LOD）で対応する。

## ゴール

- ドラッグ・ピンチ・展示モードの自動回転など、カメラが動いている間だけ大幅に簡略化したモデルを表示し、操作のfpsを改善する
- カメラが静止したら自動的に元の精密なモデル表示に戻す
- 既存の変換済みモデル（軽量版ファイルを持たない）は今まで通り動作する（後方互換）
- タップによる部品選択のような「動きを伴わない」操作では切り替えが起きない（ちらつき防止）

## スコープ外（今回やらないこと）

- 既存の変換済みモデルの一括再変換（新規変換分のみ対応。既存モデルは必要になれば手動で再変換すればよい）
- 軽量表示中の部品ごとの表示/非表示・タップ選択・注釈連動（軽量版は「見た目の代役」であり、部品単位の状態は持たない）
- 軽量表示中であることを示すUI上の表示（ちらつき防止を優先し、視覚的な切り替えのみで通知しない）
- ドラッグ&ドロップで読み込んだ単体GLBファイルへのLOD適用（サーバー経由（ギャラリー/URL指定）で読み込んだモデルのみ対象。巨大アセンブリは基本的にサーバー経由での運用のため）

## 既知の制約（ユーザー承認済み）

部品を「隠す」操作をした状態でカメラを動かすと、軽量版は個別部品の表示/非表示を追跡しないため、動いている間だけ隠した部品が一瞬見えてしまう場合がある。カメラが静止すれば精密表示に戻り、正しい状態（非表示のまま）に戻る。

## アーキテクチャ

### コンバータ側

`pipeline.py` の `convert()` は、通常の圧縮（`compress_glb`、既存の `-si 0.5`）に加えて、同じ生GLB（`build_glb`の出力）に対してもう一段階アグレッシブな圧縮を行い、`<out_path のstem>_lod.glb` として保存する。

`compress.py` に新関数 `compress_glb_lod(src, dst)` を追加する。既存の `compress_glb` とは別関数にする（責務を分け、通常品質の圧縮パラメータに影響を与えないため）。

パラメータ方針:
- `-si 0.05`: 三角形数を目標5%まで削減
- `-sa`: 目標比率まで強制的に簡略化する（誤差許容より比率を優先。これがあると `-se` による誤差上限指定は無効になるため付けない）
- `-cc`: 既存同様の高圧縮
- `-kn` は付けない: 軽量版は部品選択をしないためノード名保持は不要。名前でのノード結合抑止を外すことで gltfpack がより多くをまとめられ、ドローコールも減る

軽量版はテッセレーション（`tessellate()`の実行）はやり直さない。既に生成済みの生GLBバイトを再利用し、gltfpackを異なるパラメータでもう一度実行するだけなので、変換時間への追加コストは小さい。

`convert()` の戻り値の統計（`parts`/`triangles`/`size_bytes`）は通常版のみを対象とし、軽量版の数値は含めない（完了メッセージを煩雑にしないため、今回のスコープでは表示しない）。

**LOD生成の失敗は致命的にしない**: 軽量版はあくまで任意の付加物であり、ビューアは軽量版が無ければ通常表示にフォールバックする。したがって `compress_glb_lod` が失敗しても、既に生成済みの通常版GLBは有効なので変換全体は成功扱いとし、軽量版だけをスキップする（標準エラー出力に理由を残す）。これにより、アグレッシブな簡略化が特定形状で失敗しても、ユーザーは通常版を問題なく使える。

### ビューア側

**ファイル配信**: `modelsource.js` の `modelPaths(name)` に `lod: "/models/{name}_lod.glb"` を追加する。

**読み込み**: `main.js` の `loadFromServer` は、通常のGLB読み込みに続けて `_lod.glb` を `fetch` する。存在しなければ（404）何もしない。存在すれば `viewer.js` に渡す。

**軽量版の描画**: 新規モジュール `viewer/src/lod.js` を追加する。役割は「読み込んだLOD用glTFシーンから、部品ごとの表示/非表示や選択などの状態を持たない、色分けされたBatchedMeshの配列を組み立てて返す」ことだけに限定する（`parts.js`の対話的なレジストリとは責務を分離する）。`materialKey`によるグループ化ロジックは`parts.js`と共通化できる部分は関数を切り出して再利用する。

軽量版のBatchedMeshは部品選択の対象にしない（`batch.raycast = () => {}` でレイキャスト自体を無効化する）。単に「タップ操作をしない」だけでは不十分で、レイキャストを無効化しないと、`resolveHitPartName`（`parts.js`）が部品名解決用の`batchIdToName`を持たない軽量版バッチにヒットした際に例外を投げる（実装時のコードレビューで検出）。

**切り替えロジック**: `viewer.js` の `animate()` ループで、毎フレーム `camera.position` と `controls.target` を前フレームの値と比較する。移動量（距離）が `modelDiag * 1e-4` を超えていれば「動いている」と判定する（浮動小数点の微小な誤差だけでは反応しないための閾値。OrbitControlsの慣性減衰（damping）中も動き続けるため、指を離した直後の余韻運動でも軽量版のままになる）。「動いている」と判定した瞬間に軽量版を表示・精密版を非表示にし、以後動きを検知するたびに最終検知時刻を更新する。最終検知時刻から250ms経過したら、精密版を表示・軽量版を非表示に戻す。軽量版のオブジェクトは精密版と同じ親（`currentModel`）に追加し、向き・スケール・位置の変換を自動的に共有させる。

**エラー処理**: LODファイルの取得に失敗した場合（ネットワークエラー・404）、軽量版なしとして扱い、常に精密表示のまま動作する（現状の全モデルと同じ挙動）。致命的エラーにはしない。

**モデル切り替え時のクリーンアップ**: 新しいモデルを読み込む際、既存のLOD用BatchedMeshも精密版と同様に破棄する（`dispose()`）。

## データフロー

```
convert() 実行
  ├→ tessellate → build_glb → compress_glb(通常品質)      → <name>.glb
  └→                        → compress_glb_lod(大幅簡略化) → <name>_lod.glb

loadFromServer(name)
  ├→ fetch <name>.glb        → loadModel() → 精密表示（現状通り）
  └→ fetch <name>_lod.glb（あれば）→ buildLodBatches() → 軽量表示（非表示で待機）

animate()ループ毎フレーム:
  カメラ位置/注視点が変化 → 軽量版を表示・精密版を非表示
  変化なしが250ms継続    → 精密版を表示・軽量版を非表示
```

## テスト

- **コンバータ**: `compress_glb_lod` が正しいgltfpack引数（`-si`/`-se`/`-sa`）を渡すことをTDDで検証（`subprocess.run`をmonkeypatchする既存パターンを踏襲）。`pipeline.convert()` が `_lod.glb` を生成すること・軽量版ファイルが存在してもstatsは通常版のみを反映することを検証。
- **ビューア**: カメラ移動検知ロジック（動いている判定・静止判定・250ms猶予）を単体テストで検証。`buildLodBatches` がgltfシーンから正しくBatchedMeshを組み立てることを検証。LODファイルが存在しない場合に例外を出さず現状動作を維持することを検証。
- **実機確認**: 前回追加したFPS表示を使い、別PCで操作中のfpsが改善したかを実測してもらう。

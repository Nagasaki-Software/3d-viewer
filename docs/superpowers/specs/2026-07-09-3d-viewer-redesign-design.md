# 3D ビューア全面見直し 設計書

作成日: 2026-07-09
対象: `apps/3d-viewer`

## 1. 背景と目的

現行アプリは GLB/GLTF をドラッグ&ドロップで表示し、注釈を付けられるタッチ対応 3D ビューアである。
今回、以下を目的に全面的に見直す。

- 最大 500MB 級の CAD 由来 3D モデル（STEP）を快適に表示・操作できるようにする
- 拡大すれば詳細な形状まで確認できる
- 機械系エンジニアの「現場での組立・保全参照」「社内外への説明・プレゼン」用途に合った機能を備える

## 2. 前提・制約

- 元データ: 機械 CAD が出力する STEP ファイル（最大 500MB 程度）
- 対象端末: Windows タッチ対応ノート PC、大型タッチパネル・現場端末（ブラウザは Chrome / Edge 想定）
- 運用: 事前変換ツールで表示用ファイルを作成し、それをビューアにドロップする
- 部品単位の操作（タップで部品名表示、非表示・強調）が必要
- ネット接続がない環境でも、ビューアを開いた後の操作はローカルで完結する
- メモリ消費を極力抑える（dev 全体の方針）
- フォントはメイリオを優先する

## 3. 全体構成

```
[CADソフト] → STEPファイル (〜500MB)
     ↓
[変換ツール]  … Windows 用 Python GUI アプリ（新規作成）
     ↓ 部品名・階層・色を保持したまま軽量化
表示用ファイル (.glb / meshopt 圧縮 / 数十MB程度)
     ↓ ドラッグ&ドロップ
[3Dビューア]  … 現行 Vite + Three.js アプリを強化
```

構成要素は 2 つ。リポジトリ内のディレクトリ構成は以下とする。

```
apps/3d-viewer/
├── converter/   # 変換ツール（Python）
└── viewer/      # ビューア（既存 src/ を再編）
```

## 4. 表示用フォーマット

**glTF (GLB) + meshopt 圧縮（EXT_meshopt_compression）** を採用する。

- glTF は Web 3D の業界標準。部品の階層・名前・色をノード構造としてそのまま保持できる
- meshopt 圧縮は形状データを 1/5〜1/10 に縮小し、Three.js 標準の MeshoptDecoder で高速に展開できる
- 500MB の STEP は変換後おおむね 30〜80MB になる見込み（形状の複雑さに依存）

Draco 圧縮は展開が重くメモリ消費も大きいため採用しない。サーバー配信型（3D Tiles 等）は
オフライン現場利用と相性が悪く、本規模には過剰なため採用しない。

## 5. 変換ツール（converter）

### 形態

- Windows 用の Python GUI アプリ（tkinter、メイリオ）。将来 PyInstaller で EXE 化して配布できる作りにする
- 操作は「STEP ファイルを選ぶ → 品質を選ぶ → 変換ボタン」の 3 ステップのみ

### 処理内容

1. **STEP 読み込み**: OpenCascade（CadQuery 経由の OCP バインディング）の XDE 機能で読み込み、
   アセンブリ階層・部品名・色を取得する
2. **メッシュ化**: 品質設定に応じた許容誤差（deflection）でテッセレーションする
   - 品質は「粗い / 標準 / 細かい」の 3 段階。既定は「標準」。細かいほど拡大時に滑らかだがファイルが大きい
3. **エッジ生成**: CAD の正確な稜線（BRep エッジ）を折れ線化し、glTF の線プリミティブとして
   部品ノード配下に埋め込む（ビューアの輪郭線表示に使用）
4. **glTF 出力**: 部品 = ノードの階層構造で GLB を組み立てる。部品名はノード名に格納する
5. **圧縮**: meshoptimizer 付属の gltfpack で meshopt 圧縮を適用する

### 使用ライブラリ（いずれも GitHub 1000 スター超・活発に更新中）

| ライブラリ | 用途 |
|---|---|
| CadQuery / OCP | STEP 読み込み・テッセレーション（OpenCascade バインディング） |
| meshoptimizer (gltfpack) | GLB の meshopt 圧縮・最適化 |

依存パッケージ導入時は package-security-scan スキルでスキャンし、ユーザーの承認を得る。

### エラー処理

- 壊れた STEP・読み込み失敗・メモリ不足は、原因をわかりやすい日本語メッセージで表示する
- 変換中は進捗（読込 → メッシュ化 → 圧縮）を段階表示し、フリーズと誤解されないようにする

## 6. ビューア（viewer）

現行の Vite + Three.js 構成・モジュール分割（viewer / annotations / storage / ui）を土台に強化する。

### 6.1 大型モデルの高速表示と安定ズーム

- GLTFLoader に MeshoptDecoder を設定し、圧縮 GLB を直接読み込む
- 部品ごとに形状をひとまとめにして描画回数を削減する（部品 = 1 メッシュ）。
  それでも不足する場合は BatchedMesh の導入を検討する（初期実装には含めない）
- ピクセル比上限（現行 2）とジオメトリ・マテリアルの破棄処理（現行実装）を維持する
- **ズーム安定化**:
  - OrbitControls の zoomToCursor を有効にし、指の位置に向かってズームする
  - カメラの near/far をズーム距離に応じて毎フレーム自動調整し、極端な拡大時の
    ちらつき（Zファイティング）や手前欠けを防ぐ
  - モデルのバウンディングボックスから minDistance / maxDistance を自動設定する

### 6.2 部品操作（タップ選択）

- 部品タップ → ハイライト表示 + 部品名と操作ボタン（**隠す / 強調 / すべて再表示**）を表示
- 空きスペースのタップで選択解除
- タップとドラッグ（回転）は移動量しきい値で区別し、誤操作を防ぐ

### 6.3 表示機能

- **エッジ表示**: 変換時に埋め込んだ稜線データの表示 ON/OFF。ON で CAD 図面風の輪郭線付き表示になる
- **標準ビュー**: 正面・背面・上・下・左・右・等角の切替ボタン。カメラはなめらかに補間移動する
- **明るい背景モード**: ダーク / ライトをワンタップ切替。ラベル・線・UI の配色も連動して切り替える

### 6.4 注釈の強化

- ラベルは部品に紐づく（部品ノード名 + ローカル座標で保持し、部品の表示状態に追従）
- アンカー点への引出し線（リーダーライン）付き
- 注釈一覧パネルを設け、選択するとその注釈へカメラが移動する
- 既存の注釈 JSON（v1: annotations のみ）は互換読み込みを維持する

### 6.5 視点ブックマーク

- 保存内容: カメラ位置・注視点、部品の表示/非表示状態、背景モード
- 名前を付けて保存し、一覧から選ぶとその状態をなめらかに再現する
- プレゼンで「見せたい順」に登録して使うことを想定する

### 6.6 データ保存（JSON v2）

```json
{
  "version": 2,
  "modelFile": "model.glb",
  "annotations": [
    { "id": "...", "label": "...", "partName": "...", "position": { "x": 0, "y": 0, "z": 0 } }
  ],
  "bookmarks": [
    {
      "id": "...", "name": "...",
      "camera": { "position": {}, "target": {} },
      "hiddenParts": ["..."],
      "background": "dark"
    }
  ]
}
```

- v1（version フィールドなし・annotations のみ）は読み込み時に v2 へ変換する
- 保存はこれまで同様、JSON ファイルのダウンロード方式とする

### 6.7 画面デザイン

- 実装段階で、まず ui-ux-pro-max で配色・スタイル・UX 指針の設計システムを決め、
  その後 frontend-design で画面を実装する（指針 → 実装の順）
- タッチ前提の大きめボタン（最小 44px）、メイリオ優先、明暗両モード対応

## 7. テスト

- **変換ツール**: 小さな STEP フィクスチャを使った自動テスト（pytest）。
  階層・部品名の保持、品質設定によるメッシュ量の変化、エラーメッセージを検証する
- **ビューア**: データ処理部分（storage の v1/v2 変換、ブックマークのシリアライズ等）を
  Vitest で自動テストする。3D 描画・タッチ操作は手動確認チェックリストで検証する
- **性能確認**: 変換済みの大型モデル（圧縮後 50MB 級）で、読み込み時間・操作フレームレート・
  メモリ使用量を実機（タッチ対応 Windows PC）で確認する

## 8. 対象外（今回は実装しない）

- 断面表示、分解表示（エクスプロード）
- 距離計測、部品寸法表示、部品ツリーパネル
- プロジェクト 1 ファイル保存（モデル同梱）、PWA / オフラインインストール
- サーバー配信・ストリーミング

これらは将来の拡張候補として、今回の設計（部品ノード構造・JSON バージョン管理）で
拡張の妨げにならないようにしておく。
